# 문서 작성 규칙

> 이전: [아키텍처](../README.md)

이 문서는 dotori-docs에 문서를 추가하거나 고칠 때 지키는 규칙을 설명합니다.

## 독자

| 독자 | 하는 일 | 멈추는 깊이 |
| --- | --- | --- |
| 운영자 (도입 검토 포함) | 설치하고 운영합니다. 인프라 전문가가 아닐 수 있습니다 | L1 |
| 통합 개발자 | API, CLI, 동기화 클라이언트로 연동합니다 | L1과 조회 문서 |
| 기여자·유지보수자 | 구조를 이해하고 바꿉니다 | L3 |

## 깊이

깊이는 독자가 치르는 전문성 비용입니다. 내려갈수록 요구하는 지식이 늘고, 각 문서는 어디서 멈춰도 되는지 알 수 있어야 합니다.

| 수준 | 폴더 | 답하는 질문 | 분량 목표 | 어휘 |
| --- | --- | --- | --- | --- |
| L0 소개 | overview/ | Dotori가 무엇이고 나에게 맞는가 | 1,500자 안팎 | 제품 용어만 |
| L1 개요 | overview/ | 무엇이 어떻게 돌아가는가 | 6,000자 안팎, 도식 중심 | 서비스 이름과 명령. 소스 경로와 패턴 용어 금지 |
| L2 구조 | architecture/ | 어떤 블록이 무엇을 소유하는가 | 블록당 문서 하나 | 패키지 경로와 패턴 용어 허용 |
| L3 규칙·내부 | architecture/ | 어떤 규칙을 왜 지키는가 | 필요한 만큼 | 클래스, 함수, 테스트 이름 허용 |
| 방법 | guides/ | 이 일을 어떻게 하는가 | 작업 하나당 문서 하나 | 독자의 어휘 |
| 조회 | reference/ | 이 값이나 계약은 무엇인가 | 항목 단위 | 정확한 이름 |

분량 목표는 한글 기준의 임시 값이며, 넘으면 하위 문서로 내립니다.

## 이전·다음 링크

제목 바로 아래에 이전과 다음에 읽을 문서를 한 줄로 둘 수 있습니다. 문서가 하나의 읽는 순서에 속할 때만 쓰고, 순서가 없는 문서는 생략합니다. 독자와 깊이는 문서 안에 적지 않고 폴더(overview, guides, reference, architecture)와 위의 표가 나타냅니다.

```markdown
> 이전: [Dotori란 무엇인가](./what-is-dotori.md) · 다음: [아키텍처](../architecture/README.md)
```

## 어휘

overview/ 문서에는 다음을 쓰지 않습니다.

- `app/` 같은 소스 경로, 클래스와 함수 이름
- 설계 패턴 용어. 마이크로커널, DDD, aggregate, Ports and Adapters

서비스 이름(app, orchestrator, executor)과 운영자가 직접 입력하는 명령과 파일(`install.py`, `.env`)은 쓸 수 있습니다.

## 링크

- 문서 사이의 참조는 장 번호가 아니라 링크로 합니다. 문서가 나뉘면 번호가 깨집니다.
- dotori-docs에서 dev-docs로는 링크하지 않습니다.
- 상세 문서로는 자유롭게 링크하고, 상위 문서는 이전 링크로 가리킵니다.

## 문체와 표현

- 문체는 합니다 체로 통일합니다. 작업 순서를 안내하는 `guides/`의 문서는 독자에게 직접 말하는 "~하세요"를 함께 쓸 수 있습니다. 한다 체는 어디에도 쓰지 않으며 테스트가 검사합니다.
- 코드, 설정, 화면에 그대로 나오는 이름(job, receipt, executor, Provider, Orchestrator)은 영어로 씁니다. 그 밖의 말은 한글로 쓰고 필요하면 괄호에 영어를 붙입니다.
- 영어 용어는 문서에서 처음 쓸 때 풀이하거나 [용어집](../../reference/glossary.md)으로 연결합니다.
- 한 칸에 명사를 나열하지 않고 문장으로 씁니다. 표는 값을 찾아보는 데 쓰고 설명을 담지 않습니다.
- 흐름과 관계는 도식(mermaid)으로 보여 주고, 표는 조회와 비교에 씁니다.
- 한 문서에는 한 가지 목적만 담습니다. 다른 목적의 내용은 하위 문서로 내립니다.

## 새 문서를 만들 때

제목 아래에 목적 한 문단, 작성 예정 내용, 다루지 않는 것을 먼저 적습니다. 범위를 선언한 뒤에 본문을 채우면 문서가 다른 주제로 번지지 않습니다.
