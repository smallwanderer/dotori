# 검증 등급

> 이전: [Provider](../architecture/crosscutting/provider.md) · 다음: [임베딩 Provider 선택과 후보 검증](../guides/operate/embedding-provider-validation.md)

이 문서는 Provider 선언이 실제로 검증되었는지를 나타내는 세 등급과 그 근거의 의미를 설명합니다.

## 세 등급

카탈로그의 함수 선언(예: 임베딩 프로필의 `text.embed`)은 등급 하나를 가집니다. 이름이 같은 모델이어도 등급은 모델, 실행 대상, 백엔드 조합마다 따로 정해집니다.

| 등급 | 뜻 | 요구하는 근거 |
| --- | --- | --- |
| `declared_unverified` | 선언만 있고 확인한 근거가 없습니다 | 선언을 설명하는 참조(`declaration_ref`)가 필요하고, 검증 근거(`evidence_ref`)는 둘 수 없습니다 |
| `contract_verified` | 호출 계약을 지키는 것을 확인했습니다 | 통과한 검증 근거(`evidence_ref`)가 필요합니다 |
| `quality_verified` | 계약에 더해 품질 기준을 넘는 것을 확인했습니다 | 계약 검증 근거에 더해 버전이 있는 수용 기준과 지표별 임계값을 모두 충족해야 합니다 |

검증 근거는 `llm_installation/evidence/` 아래의 버전이 있는 JSON 파일이며, 모든 계약 검사가 통과하고 실패 항목이 없어야 근거로 인정됩니다. 확인하지 않았다는 사실을 숨기지 않으려고, 근거가 없는 선언은 근거 파일을 가리키지 못하게 막아 둡니다.

## 등급에 따른 사용 범위

| 선택 방식 | 허용되는 등급 |
| --- | --- |
| 명시 선택 | 선언된 후보라면 등급을 따지지 않습니다. 대상이 꺼져 있으면 거부합니다 |
| 기본 경로 | `quality_verified`입니다. `text.embed`와 `text.generate`는 `contract_verified`도 허용합니다. `declared_unverified`는 기본 경로가 되지 못합니다 |

기본 경로가 가리키는 후보가 이 조건을 넘지 못하면 배포 계획을 읽을 때 거부됩니다([등록부](../architecture/blocks/registry.md#배포-계획-snapshot)). 자격이 되는 후보가 둘 이상이면 하나를 명시해야 하고, 하나도 없으면 오류입니다.

## 근거가 가리키는 대상

근거는 모델 이름이 아니라 실행 조합 하나를 가리킵니다. 근거 파일은 다음을 기록합니다.

- **모델**: 모델 id와 revision
- **실행 대상**: 대상 id와 revision, artifact 해시, 백엔드 id와 버전, 어댑터 계약
- **처리 방식**: 입력 전처리 버전, 출력 해석 버전, 시험한 추론 옵션
- **시험 자체**: fixture 묶음의 id와 revision, 평가기 버전, 실행 시각, 표본 수, 계약 검사 항목별 결과, 지표

## 같은 이름이라도 그대로 적용할 수 없는 이유

카탈로그를 읽을 때 근거의 함수, 등급, 모델 id, 모델 revision이 선언과 같아야 하고, 실행 대상과 백엔드도 근거에 적힌 조합과 맞아야 합니다. 하나라도 다르면 카탈로그가 거부됩니다. 백엔드 버전이나 전처리, 출력 해석, 추론 옵션이 달라지면 같은 모델이어도 다른 동작을 할 수 있기 때문입니다. 근거는 옵션의 범위도 함께 기록할 수 있어서, 시험하지 않은 범위의 옵션에는 적용되지 않습니다.

## 선언의 등급과 개별 요청의 상태

등급은 오프라인에서 확인한 근거에 대한 주장이고, 지금 이 요청이 성공할지는 별개입니다. 요청의 성공은 서비스의 상태 확인, 기능 활성 판정, 임베딩 admission 같은 실행 시점의 검사가 따로 정합니다. 등급이 높다고 서비스가 지금 건강하다는 뜻은 아니며, 등급이 낮아도 명시적으로 선택한 대상은 실행됩니다.

다루지 않는 것: 검증을 수행하는 명령은 [임베딩 Provider 선택과 후보 검증](../guides/operate/embedding-provider-validation.md)이, 검증 대상인 Provider 구조는 [Provider](../architecture/crosscutting/provider.md)가 다룹니다.
