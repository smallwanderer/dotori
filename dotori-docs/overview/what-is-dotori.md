# Dotori란 무엇인가

> 이전: [Dotori 문서](../README.md) · 다음: [동작 방식](./how-it-works.md)

Dotori는 운영자가 가진 파일을 서버에 올려 미리 처리해 두고, 준비된 결과를 웹 UI와 검색, 질의응답(RAG), 외부 AI 클라이언트가 다시 쓰게 하는 셀프호스팅 제품입니다. 로컬 환경에서 파일과 AI를 연결하는 것이 목적이며 RAG는 활용 방법 중 하나입니다. 현재 문서 처리를 제공하고, 이미지·음성·영상의 별도 처리 기능은 이후 선택형 확장의 목표입니다.

## 지원하는 파일 형식

PDF, 한글(HWP, HWPX), Word, Excel, PowerPoint, 텍스트와 마크다운, HTML, 이미지 파일을 분석 대상으로 처리합니다. 그 밖의 파일 형식은 단순 저장 및 조회만이 가능합니다. 전체 목록은 [지원하는 파일 형식](../reference/supported-formats.md)에 있습니다.

## 무엇을 할 수 있나요

- 개인·팀 워크스페이스의 권한으로 폴더와 파일을 관리합니다.
- 올린 문서를 분석해 두고 자연어로 검색합니다.
- 문서 근거를 제공해 질문에 답하고 출처를 보여 줍니다. 모델의 모든 답변이 정확하다는 보장은 아니므로 중요한 내용은 원문을 확인합니다.
- 웹 UI, CLI, HTTP API와 읽기 전용 MCP로 권한이 허용하는 원본·처리 결과에 접근합니다. 인터페이스마다 제공하는 기능은 다를 수 있습니다.

## 네 가지 원칙

- Full-Stack: 업로드부터 처리, 검색, 질의응답, 장애 복구까지 하나의 제품으로 제공합니다.
- Modular: 새 자료 유형을 추가할 때 기존 처리 방식을 고치지 않도록 설계했습니다.
- Lightweight: 선택 설치에서 고르지 않은 기능의 모델과 서비스는 올리지 않습니다. 필요한 메모리와 준비 시간은 선택한 기능·모델·입력에 따라 다릅니다.
- Self-Hosted: 서버, 원본, 결과, 권한을 운영자가 직접 통제합니다. 외부 모델을 직접 선택하면 그 모델로 문서 내용이 전달됩니다.

## 설계를 정한 제약

- 설치 마법사는 하드웨어를 확인해 서버 공통 모델과 실행 방식을 정합니다. 임베딩 모델은 서버 공통으로 하나를 사용하고, 관리형 로컬 LLM도 선택한 하나를 실행합니다. 외부 LLM endpoint는 여러 개 등록할 수 있습니다.
- 가벼운 실행. 개인 PC에서 동작할 수 있는 시스템 제약조건을 바탕으로 개발하고 있습니다.
- No-Coding. 기본 로컬 설치와 실행은 마법사로 진행합니다. 외부 HTTPS 접속은 도메인과 인증서 설정이 추가로 필요합니다.
- 한국어를 먼저 씁니다. 설치 화면, 환경 변수 예시, 운영 문서가 한국어를 우선합니다.

## 누구를 위한 것이고 무엇을 하지 않나요

개인이나 소규모 그룹이 서버 한 대에 직접 설치해 운영하는 경우를 위한 제품입니다.

- 여러 서버에 나누어 배포하는 구성을 전제로 하지 않습니다. 즉, K8s와 같은 아키텍처 구성을 가정하고 있지 않습니다.
- 이미지 분석, 음성, 영상 처리는 *현재* 제공하지 않습니다. 이미지 파일은 문서와 같은 방식으로 글자를 추출합니다. 새 자료 유형은 이후 선택적으로 추가할 수 있게 설계했습니다.

구성요소와 흐름은 [동작 방식](./how-it-works.md)에서, 설치는 [설치 가이드](../guides/install/installation-guide.md)에서 이어집니다.
