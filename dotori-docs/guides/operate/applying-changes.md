# 설정 변경 적용

> 이전: [운영 가이드](./operation-guide.md) · 다음: [임베딩 런타임 가이드](./embedding-guide.md)

모델이나 설정을 바꾸는 작업은 선택을 파일에 기록하는 것으로 끝나지 않습니다. 실행 중인 프로세스는 그 파일을 다시 읽지 않으므로, 적용은 프로세스가 재시작될 때 일어납니다.

## 세 단계

| 번호 | 단계 | 확정되는 것 | 운영자가 하는 일 |
| --- | --- | --- | --- |
| 1 | 코드와 이미지 | 선택할 수 있는 항목의 목록 | 없음. 제품 버전이 정합니다 |
| 2 | 설치와 명시적 변경 | 선택된 항목과 확정 값 | 변경 명령을 실행합니다 |
| 3 | 프로세스 재시작 | 그 선택이 실제로 적용됩니다 | 변경에 따라 직접 재시작이 필요합니다 |

운영자가 수행하는 작업은 두 번째 단계입니다. 세 번째 단계는 변경 명령이 대신 해 주는 경우와 직접 해야 하는 경우로 나뉩니다.

## 변경별 적용 방법

| 바꾼 것 | 기록되는 곳 | 적용 |
| --- | --- | --- |
| 임베딩 런타임 | `embedding_runtime.json` | `python install.py --change-embedding`이 중지, 활성화, 재시작까지 수행합니다. 재시작이 실패하면 이전 세대로 되돌립니다 |
| LLM 런타임 | `llm_runtime.json` | `python install.py --change-llm`이 런타임 컨테이너를 전환합니다. 서비스 프로세스의 반영은 `python install.py --restart`에서 일어납니다 |
| 로그인 요구 여부 | `.env` | `python install.py --login enable\|disable`이 재시작 여부를 묻습니다 |
| 처리량, 검색 기본값, 파서 backend 등 `.env` 값 | `.env` | `python install.py --restart`가 필요합니다 |
| 설치 모드와 활성 기능 | `deployment_plan.json` | 설치 절차가 서비스를 다시 올립니다 |

직접 재시작이 필요한 항목을 건너뛰면 파일에는 새 설정이 있고 프로세스는 이전 설정으로 동작합니다. 이 상태에서 요청이 거부되거나 이전 대상으로 처리될 수 있습니다.

## 적용되었는지 확인하기

```bash
python install.py --status
```

임베딩 런타임은 [임베딩 런타임 가이드](embedding-guide.md#verify)의 확인 절차를, LLM 런타임은 [LLM 설치 가이드](../install/llm-installation-guide.md)의 헬스체크를 사용합니다.

## 알아두어야 할 것들

- 변경 명령은 자기 프로세스에서 실행됩니다. 명령이 성공했다는 사실이 실행 중인 서비스에 반영되었다는 뜻은 아닙니다.
- 재시작은 서비스 단위입니다. 임베딩 변경은 `app`과 처리 서비스를 함께 교체합니다.
- 파서 backend는 설정 파일이 아니라 환경 변수에서 읽습니다. 설치 계획만 바꿔서는 변경되지 않습니다.
- 모델을 바꾸면 기존 벡터와의 호환을 판단해야 합니다. 재임베딩이 필요한 경우가 있습니다.
