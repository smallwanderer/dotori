# 첫 문서로 시작하기

> 이전: [설치 가이드](../install/installation-guide.md) · 다음: [운영 가이드](../operate/operation-guide.md)

설치한 서버에 문서 하나를 올리고, 선택한 구성에서 처리와 검색이 동작하는지 확인합니다. 처음에는 짧은 텍스트나 Markdown 파일로 시작하면 처리 상태를 확인하기 쉽습니다.

## 1. 서버와 작업공간 확인

브라우저에서 `http://127.0.0.1:8000`으로 접속합니다. 기본 로컬 모드에서는 관리자 프로필로 자동 접속하고, 로그인 필수 모드에서는 계정으로 로그인합니다. 파일을 보관할 작업공간을 선택합니다. 다른 작업공간의 파일은 현재 목록과 검색 대상에 포함되지 않습니다.

설치 구성에 따라 사용할 기능이 다릅니다.

| 구성 | 확인할 수 있는 기능 |
| --- | --- |
| 기본 | 파일 업로드·목록·다운로드 |
| Documents 추출 | 위 기능과 문서 텍스트·구조 추출 |
| Hybrid/Search AI | 위 기능과 의미 검색 |
| Full 로컬 AI RAG | 위 기능과 LLM 답변 생성 |

검색에는 임베딩이, 질의응답에는 검색과 사용 가능한 LLM endpoint가 필요합니다. 외부 모델 연결은 [임베딩 가이드](../operate/embedding-guide.md)와 [운영 가이드](../operate/operation-guide.md)를 참고합니다.

## 2. 문서 업로드

다음 내용을 `first-document.md`로 저장하고 파일 화면에서 업로드합니다.

```markdown
# 도토리 시험 문서

이번 시험의 확인 코드는 ACORN-040입니다.
회의는 금요일 오후 3시에 진행합니다.
```

업로드 후 목록에 파일이 나타나면 원본 저장이 끝난 것입니다. 검색까지 사용하려면 업로드할 때 문서의 AI 처리를 켭니다. AI 처리를 끈 파일은 저장되지만 자동 분석 대상이 되지 않습니다.

## 3. 처리 완료 확인

문서 상세에서 파싱과 임베딩 상태를 확인합니다. 업로드 성공은 검색 준비 완료와 다릅니다. 파싱과 임베딩이 완료되기 전에는 검색되지 않을 수 있습니다.

기본 모드에서는 처리 단계가 실행되지 않고, 추출 모드에서는 임베딩이 실행되지 않는 것이 정상입니다. 지원하지 않는 형식은 원본 보관만 가능합니다. [지원 형식](../../reference/supported-formats.md)을 확인합니다.

## 4. 검색과 질의응답

검색이 활성화된 구성에서는 `회의 시간`을 검색합니다. 시험 문서와 관련 내용이 결과에 나타나는지 확인합니다.

LLM이 연결된 구성에서는 해당 문서를 대상으로 `시험의 확인 코드는 무엇인가요?`라고 질문합니다. 답변의 `ACORN-040`과 출처를 원문과 비교합니다. 문서 내용이 짧아도 모델 준비와 추론에 시간이 걸릴 수 있습니다.

답변의 출처는 내용을 확인할 근거이며 정답 보장은 아닙니다. 검색이 성공하고 답변 생성만 실패하면 LLM 연결 상태를 별도로 확인합니다.

## 대기하거나 실패한다면

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 파일이 목록에 없음 | 현재 작업공간, 업로드 응답과 저장 용량을 확인합니다 |
| 처리 대기 | AI 처리 활성 여부와 설치 모드를 확인합니다. 다른 문서를 처리 중이라면 기다립니다 |
| 파싱·임베딩 실패 | 문서 상세의 실패 사유와 운영 요약에서 실행 서비스 상태를 확인합니다 |
| 검색 결과 없음 | 임베딩 완료, 작업공간과 문서 검색 범위를 확인합니다 |
| 검색은 되지만 답변 생성 실패 | 선택한 LLM endpoint와 런타임 상태를 확인합니다 |

계속 진행되지 않으면 서버를 운영하는 사람이 `python install.py --status`와 [운영 가이드의 복구 절차](../operate/operation-guide.md#문서-파이프라인-복구가-필요함)를 확인합니다. 원인을 확인하기 전에 파일을 반복 업로드하거나 큐를 삭제하지 않습니다.
